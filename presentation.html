02 — Docker vs Natif

Pourquoi on a pivoté

Une décision pragmatique prise sous contrainte de temps — et la bonne sur le fond.

⚠️ Le problème — Docker Desktop sur Windows Server 2022

On a essayé de déployer l'application via Docker Desktop pour simplifier le tout. Sauf que Windows Server 2022 fait de la résistance sur la virtualisation imbriquée (WSL2). Résultat : des heures bloquées sur des erreurs de noyau, des commandes DISM qui échouent, et des problèmes d'installation MSI impossibles à débloquer proprement.

✓ La décision — Déploiement natif

Pour ne pas risquer la date de rendu, on a pris la décision de déployer l'application directement sur l'OS. C'est plus robuste, plus facile à déboguer, et ça évite les couches de virtualisation inutiles pour notre contexte de demo.

Chronologie du pivot

Tentative Docker Desktop

Installation Docker Desktop + WSL2 sur Windows Server 2022. Blocage sur la virtualisation imbriquée (Hyper-V + VirtualBox + WSL2 = conflit de noyau).

Tentatives de déblocage

DISM, activation/désactivation de features Windows, réinstallations MSI, recherches de workarounds. Résultat : heures perdues sans solution stable.

Décision de pivot

Arbitrage coût/bénéfice : Docker est un outil de déploiement, pas le projet. On abandonne la conteneurisation pour cette demo et on déploie nativement.

Déploiement natif opérationnel

PostgreSQL installé en dur. Python + Node.js natifs. Front et back démarrés en processus persistants. Tout fonctionne.

04 — Plan de match

Ce qu'il reste à faire

Trois tâches d'admin sys pour boucler le projet. L'appli est prête — c'est l'infrastructure qui finalise.

1

VM Client — Jonction Active Directory

Tâche : finaliser VM_Client_TP
  • Configurer la VM client pour qu'elle pointe vers SRV-YMMO-AD comme serveur DNS.
  • Joindre la machine au domaine Active Directory géré par SRV-YMMO-AD.
  • Vérifier que le client peut ouvrir une session avec un compte de domaine.
  • Naviguer sur le site web Ymmo depuis le réseau local (via l'IP de SRV-YMMO-WEB).
2

VPN IPSec — Le boss final

Tâche : configurer le tunnel sur SRV-PFSENSE-GW
  • Configurer le tunnel IPSec site-à-site sur l'interface pfSense de SRV-PFSENSE-GW.
  • Définir les paramètres de phase 1 (IKE) et phase 2 (ESP) : algorithmes, PSK, subnets.
  • Valider la connectivité chiffrée entre le siège (Aix-en-Provence) et une agence simulée.
  • Tester le ping cross-site à travers le tunnel.
3

Supervision (optionnel)

Tâche : Zabbix ou GLPI pour les derniers points
  • Évaluer si le sujet impose explicitement une solution de supervision pour les points bonus.
  • Si oui : déployer une VM légère avec Zabbix ou GLPI pour monitorer les serveurs.
  • Configurer des agents sur SRV-YMMO-WEB et SRV-YMMO-AD pour remonter les métriques.
📌

En résumé : L'appli tourne, le réseau est en place. Reste à faire communiquer le client avec le serveur via notre AD, ouvrir les vannes du VPN, et éventuellement ajouter la supervision pour gratter les derniers points.
